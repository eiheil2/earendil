# Earendil Web profile

The local browser profile mounts the unmodified DeepSeek Harness `AppFrame`, `SidebarRoot`, `HeroShell`, `UserContent`, and `MarkdownText` from `vendor/deepseek-web`, together with their original icons, controls, CSS Modules, and semantic theme tokens. The Pi adapter supplies layout state and slot contents; Pi's existing SessionDirectory, SessionManagement, Transcript, AgentController, and Models services supply data over authenticated POST/SSE. Assistant text uses DSH's Markdown renderer with code highlighting and math support. The original composer, session browser, and tool cards remain to be integrated. This is a partial component migration, not the complete DSH application or slot runtime.

Install with `npm --prefix apps/web-profile install --ignore-scripts`, then run `npm --prefix apps/web-profile run bundle`. Start a Pi experimental server with `startServer({ web: { port: 3080 } })`. Set `PI_WEB_BACKEND` to its loopback URL, `PI_WEB_TOKEN` to `runtime.web.token`, and `PI_WEB_SERVER_ID` to `runtime.serverId`, then run `npm --prefix apps/web-profile start`. Open `http://127.0.0.1:3081/` and enter that server ID and token. `PI_WEB_PORT` selects a different profile port. This sidecar requires a running Pi backend; it does not start a model or Session worker itself.

The experimental backend uses Unix sockets on POSIX and named pipes on Windows. With dependencies installed, double-click `start-earendil.cmd` at the repository root on Windows, or run `npm --prefix apps/web-profile run start:local` from the root. The launcher bundles the UI locally, starts the backend and profile on available ports, generates a process token, and opens a browser that connects automatically. No Server ID or token entry is required for that launch. Pass `-- --no-open` to suppress browser opening. `PI_WEB_BACKEND_PORT`, `PI_WEB_PORT`, and `PI_WEB_TOKEN` optionally override the generated settings. Optional `PI_PROVIDER` and `PI_MODEL` select the model; provider credentials stay in environment variables. Node must support native TypeScript stripping and `module.registerHooks` (the current checkout uses Node 26). Windows process integration is covered by `npm --prefix apps/web-profile run test:windows`, without a model request. Unix socket directory discovery remains POSIX-only. Reloading after the credential fragment has been consumed currently requires launching a fresh browser session or entering the connection settings manually.

Static assets are public and contain no credentials. Transport routes require the process token. An optional launch fragment `#serverId=...&token=...` is consumed and removed from the address bar; credentials remain in memory. Provider API keys never enter the browser. All npm commands run locally and do not trigger cloud builds.

The bundle includes DeepSeek's MIT license at `/LICENSE.deepseek`. Upstream source verification uses `node scripts/vendor-dsh-web.mjs --check` from the repository root.
